# How to make a set of game assets

*How-to guide, for a lead or teammate who needs several related 3D assets, texture sets or materials made, checked and documented at once.*

This guide shows you how to produce a family of assets with the
`asset-batch` workflow and ship it as a pull request.

1. **Check the project is ready.** The profile must name the asset folder, the
   manifest, the provenance log and the validator command. Budgets are optional;
   the workflow proposes them if missing. If the project has quality tiers,
   its visual target should list them.
2. **Write one line per asset**: a logical name following the project's naming
   pattern, a brief that says what it is and what it must communicate, and
   its `kind` (`mesh`, `texture-set`, `material` or `shader-material`).
3. **Name the generator if one script makes the set.** Texture sets and
   materials that one generator writes are made by one agent in one run;
   pass the script as `generator` so the plan treats the whole run as one
   make unit.
4. **Run the workflow:**

   ```
   asset-batch  args: {
     family: "dockside props",
     wp: "WP-12",
     generator: "tools/gen_dock_textures.py",
     assets: [
       { name: "T_Planks", brief: "weathered dock planks, matte, sits behind the props", kind: "texture-set" },
       { name: "MI_Brass", brief: "brass fittings on pickups, must read as metal in greyscale too", kind: "material" },
       { name: "MI_HazardPaint", brief: "hazard paint on explosive barrels, must not be confused with pickups", kind: "material" }
     ]
   }
   ```

   Omit `wp` when the work is not a work package. Pass `capture: false`
   only if you will judge the look some other way.

5. **Read the result.**
   - `status: "done"`: assets, manifest, provenance, docs and look-dev
     frames are on a pushed branch with a draft PR. `before` and `after`
     list the frames.
   - `status: "blocked"`: read `stage` and `open`; each item names the
     asset or frame and the problem. Fix or re-brief, then run again.
   - `done-docs-unverified`: review the docs pages by hand.
   - Read `notes` either way: they say whether frames were captured and
     whether every generator regenerated byte-identically.
6. **Ship it.** Run the command in `next`: with a work package,
   `/engineering-practices:deliver-package` with `prior` set to the whole
   result; otherwise `/engineering-practices:land-pr`.

If you want variants of one idea, give them the same base name (`SM_Crate_01`,
`SM_Crate_02`); the plan step will usually choose one shared generator.

If two assets must not share a material, say so in their briefs.

If the project does not say whether generated files are committed, the
plan chooses: large or binary outputs are built, not committed. Add the
rule to the project profile to make the choice explicit.
